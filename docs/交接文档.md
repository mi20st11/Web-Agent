# 交接文档

写给下一个接手的人（或下一个会话里的自己）。先读 README，这里只记“为什么这样做”和“哪里还脆”。

## 现状

v0.2，功能闭环，**已经在真实的 chat.deepseek.com 上跑通**（Windows 11 + Edge 156）。这一版把“启动前弹目录框”改成“先进界面、再选目录”，界面按 framed-sheet 重做，并加了连接状态、最近目录和记忆。

- 测试 20 个全绿，约 28 秒：协议 13、路径策略 5、真实 CDP 端到端 2（用 `test/mock-deepseek.html`）。
- 真实站点验证过两条链路：
  1. 「看目录 → 写 hello.txt → 读回来」：一轮解析出 `list` + `write` + `read` 三个工具，全部执行成功，中文内容读回一致。
  2. 「echo 你好 + node -v」：一轮解析出两个 `shell`，中文输出和 `v24.19.0` 都正确回传，模型据此给了结论。
- 危险命令审批链路在 mock 上验证：弹审批 → 拒绝 → 模型收到“用户拒绝” → 换方案。
- 工作区切换验证过：`POST /api/workspace` 切到空目录后，同一轮 `list`+`write`+`read` 写进了新目录（`ok.txt` = `done`）。
  默认提示词也因此改回直给式（见决策 10）。
- v0.2 冒烟：真实站点上一轮 `list` + 目录 `shell` + `write` + `read` 四个工具全部跑通（`smoke.txt` = `ok`），
  证明“没有启动目录、事后再选”不影响工具链。
- 界面回归：`design-taste-frontend` 的 `inspect.mjs --app` 在引导态和开始态都是 **0 FAIL**，
  只剩 1 条 WARN（工作台右侧留白 / 小字号占比），属于这类 devtools 界面的刻意选择。
- **未做**：Chrome 在真实站点上的联调（代码支持 `--browser chrome`，e2e 用 Chrome 跑过 mock）、macOS/Linux 实测、打包成单文件。

## 怎么跑

```bash
node web-agent.mjs                              # 起服务 + 界面，进去再选工程目录
node web-agent.mjs -w "D:\code\my-project"      # 直接指定工程目录
node web-agent.mjs --no-pick                    # 兼容旧参数，现在启动本来不弹框
node web-agent.mjs --no-window                  # 只起服务，打印界面地址
node web-agent.mjs --browser chrome             # 用 Chrome（独立 profile）
npm test                                        # 全部测试（会开无头浏览器）
npm run test:unit                               # 只跑协议和路径策略
```

首次启动会建独立 profile 并打开 DeepSeek，**登录一次**即可，之后复用。
Edge 用 `~/.web-agent/browser-profile`，Chrome 用 `~/.web-agent/chrome-profile`。

调试：`WEB_AGENT_DEBUG=1` 打印完整错误栈；`WEB_AGENT_BROWSER` 指定浏览器可执行文件。

## 关键决策

1. **不要扩展。** 旧版靠内容脚本 + MutationObserver，要处理 MV3 回收、消息广播、侧边栏生命周期，
   一半代码在跟浏览器打架。现在用 CDP 直接控制页面，问题只剩“页面长什么样”。
2. **独立 profile，不复用日常浏览器。** Chrome 136+ 会忽略默认 profile 上的
   `--remote-debugging-port`；独立 profile 同时也隔离了登录态。
3. **端口用 0，从 `DevToolsActivePort` 读。** 固定 9222 会跟别的工具打架，`/json/*` 在新版上也未必可靠。
4. **零依赖。** Node 22+ 自带 `WebSocket` 和 `fetch`，CDP 客户端只有 100 多行。没有 npm 安装步骤，
   clone 下来就能跑。
5. **工具协议用代码块。** 成对的中文标记又长又容易被模型改写；
   ```` ```tool ```` + 首行工具名更短，也允许一轮多个工具。同时兼容两种偷懒写法：
   围栏直接写工具名（` ```shell ` + 命令正文）、或 DeepSeek 丢掉块标签但首行正好是工具名。
6. **回传结果而不是让模型读文件。** 输出超过 8000 字符才落盘给路径，避免上下文爆炸。
7. **安全放在执行层，不放在提示词里。** `resolveInside`、`isDangerous`、备份、日志是硬约束。
   模型被网页内容带偏时，最多多一次工具调用。
8. **界面是单文件 HTML。** 无构建、无框架、SSE 推状态。
9. **发送要像人，不要像脚本。** 用 `Input.insertText` + 可信 Enter（`Input.dispatchKeyEvent`），
   失败才用真实鼠标点按钮；不要用 JS 直接改 value + `click()`。发送成功靠消息数/URL/生成中状态确认，
   因为 DeepSeek 要等服务端响应后才清空输入框，按“输入框变空”判定会误报。
10. **提示词直给，不绕弯。** 结构就是：工程目录 + 环境 + 工具块写法 + 工具清单 + 几条纪律，
    不用“结对口吻/去身份化”的包装（早期试过，已放弃）。仍然不提 agent、爬取、反代这些词，
    因为 DeepSeek 有风控；但也不伪装成人类闲聊。想换措辞不用改代码：写 `<工作区>/.web-agent/instructions.md` 整段覆盖。
11. **工程目录是运行时状态，不是启动常量。** 启动不再弹框：先起服务、开界面，浏览器在后台连；
    工作区优先级是 `-w` > `~/.web-agent/config.json` 的 `lastWorkspace` > 空。
    `Agent.setWorkspace()` 会重建 policy、tools 和提示词，界面通过 `POST /api/workspace` 触发；
    不带 body 就弹 Windows 原生文件夹选择框（`src/pick.mjs`）。切换后不自动清空对话，只提示“建议先开新对话”。
    这样将来包成 exe 时，双击就是主界面，不会先卡在一个系统对话框上。
12. **界面是 framed-sheet 工作台，不是营销页。** 侧栏 228px + 48px 顶栏共用一层 tinted ground，
    右侧一张白色 sheet（1px 边、16px 圆角、无阴影）；时间线是“动作账本”，工具调用一行一个、1px 规则分隔，
    不做卡片堆叠。空状态在纸面里垂直居中，避免下半屏一整块死白。字体 IBM Plex Sans/Mono，主色 `#1b6c80`，
    正文 14px、元信息 11–12px。改样式前先跑 `inspect.mjs --app`，保持 0 FAIL。
13. **浏览器死了要自己爬起来。** 用户关掉 DeepSeek 窗口、浏览器崩溃、或启动时进程交接，都会让 CDP 断掉。
    `web-agent.mjs` 监听自己启动的浏览器进程，退出 1.2 秒后先确认“端口还在不在、页面还在不在”：
    只是进程交接就不动；真没了就重开浏览器并重新 attach（最多 3 次，任务进行中先等它跑完）。
    所有控制台输出同时写 `~/.web-agent/app.log`，退出原因（信号 / code）也写进去，用于排查“自己退出”。

14. **等回答用自适应采样。** 开头 300ms 一次抓首段，之后 550ms；见过流式输出后，静止 900ms 即提取（原来固定 3s）。真机单轮约 4 秒，mock 端到端从 22s 降到 13s。界面字体改成异步加载（`media="print"` + `onload`），国内网络不挡首屏；生成期间状态 pill 显示“正在生成…”。
15. **空状态只留一句话。** 不再摆示例任务；引导态保留三步说明和最近目录。

16. **运行时可以换浏览器。** `POST /api/browser {"name":"edge|chrome"}` 会关掉当前实例、切到另一个浏览器的独立 profile 重连；
   选择写进 `~/.web-agent/config.json` 的 `browser` 字段。`--profile` / `--cdp` 启动时不能换（界面里置灰）。
   Chrome 首次使用需要在它自己的 profile 里登录一次；切换后如果未登录，时间线会提示。

17. **换浏览器是“先接新的，再关旧的”。** 直接关旧浏览器再连新的，会出现一段没有界面的空档；新窗口如果在 `switching:true` 期间加载，还会因为错过最后一次状态推送而让下拉永久置灰。现在的顺序是：连新浏览器 → 开新窗口 → 关旧窗口（即使旧实例不是本进程启动的也关，除非 `--keep-browser`）；失败回滚到旧连接。界面在 `switching` 为真时每 1.2 秒补拉一次 `/api/state`，SSE 重连成功也补拉一次。另外品牌图标换成了最简单的“方框 + chevron + 下划线”，同时作为 favicon（`/favicon.svg`，内联 SVG，不读文件）。

18. **单实例用 `~/.web-agent/instance.json` 锁。** 两个进程共用同一个浏览器 profile 时，任何一方切换或退出都会把共享浏览器关掉，另一边看起来就是“程序自己没了”。启动时如果记录的 pid 还活着、版本一致、`/api/health` 能通，就直接把已有界面叫到前面并退出；`--force` 绕过。这同时解释了之前“执行完自动退出”的一个真实成因：不是任务，是另一个实例在抢。

## 真实站点适配实况（改版时对照）

页面（Edge 156 / 2026-11）关键事实：

- 输入框是 `<textarea>`，**没有** `id="chat-input"`，placeholder「给 DeepSeek 发送消息 」；
  页面上还有一个不可见的 `<input>`，选择器必须按“可见”过滤。
- 发送按钮是 `div[role="button"]`，class 含 `ds-button--primary`、`ds-button--circle`；
  **没有 aria-label**；输入框为空时多一个 `ds-button--disabled`。
- 生成中没有任何 `stop` 元素，唯一可靠信号是“发送圆圈按钮去掉 disabled + 输入框为空”。
- 用户消息也是 `.ds-message`；助手正文是 `.ds-markdown.ds-assistant-message-main-content`。
- 代码块：`.md-code-block` > `.md-code-block-banner-wrap` > `.d2a24f03 span`（语言文字，如 `tool`），
  代码在紧随的 `<pre>` 里，每行一个 `<span>`，`textContent` 能还原换行。
- 提取时**必须保留换行**：把代码块换成文本节点后，普通 `white-space` 会让 `innerText` 把 `\n` 折成空格，
  导致工具块解析失败。现在替换节点带 `white-space: pre-wrap`。

已知的联动坑：

- Edge 登录微软账号后，同步会把账号里的“阻止所有 Cookie”同步到专用 profile，
  表现为 `<html>` 只有几 KB、`#root` 空、`SecurityError: sessionStorage Access is denied`。
  启动参数已加 `--disable-sync`；改本地 `Preferences` 前必须先让所有 msedge 进程退出，否则退出时会写回。
- 关闭浏览器用 `closeBrowser()`：先 CDP `Browser.close`，等 6 秒，再 `taskkill /T /F`。直接 taskkill 会留下锁文件。

## 已验证的行为（回归基线）

1. `parseToolCalls` 认：` ```tool ` + 首行工具名；围栏直接写工具名 + 命令正文；无标签但首行是工具名；
   `~~~` 与四反引号；不认普通 ```js / 未知工具；未闭合返回空；坏 JSON 产生 `error` 但不抛。
2. `resolveInside` 拒绝 `..`、绝对路径逃逸、符号链接逃逸；根目录要显式 `allowRoot`。
3. 写文件前备份，备份保留相对路径；`edit` 逐字匹配，重复出现报错。
4. 端到端（mock）：写文件任务产出 `hello.txt`，tool `status='done'`，两轮以上 assistant。
5. 端到端（mock）：危险命令触发审批，拒绝后 tool `status='error'`，日志有 `denied:true`。
6. 真实站点：`list`/`write`/`read` 一轮三工具；`shell` 中文输出；发送确认不依赖输入框清空。
7. 首轮 payload 是“提示词 + \n\n---\n\n + 任务”，mock 只解析分隔线之后的内容；工具结果轮以 `【请继续】` 结尾。
8. 端到端：切换工作区后写文件落在新目录；拒绝对话后 `pending` 清空、`busy` 归 false。
9. 无工作区启动：`/api/health` 返回 `needsWorkspace:true`，界面进入引导态（不报错、不弹框）；
   选完目录后 `needsWorkspace` 变 false、输入框启用，工作区写进 `~/.web-agent/config.json`。
10. 界面：`inspect.mjs --app` 在引导态和开始态均 0 FAIL。
11. 浏览器被关掉（强杀 Edge 进程）后，程序在约 3 秒内自动重开浏览器、重新接上页面，
    `/api/health` 回到 `connection:"ready"`，时间线多一条 notice；`~/.web-agent/app.log` 记下“浏览器不可用…正在恢复”。
12. 运行日志：每次启动写 `~/.web-agent/app.log`，含 argv、工作区、界面地址、登录状态、退出原因。
13. 运行数据不落工程目录：备份、工具输出全文、`log.jsonl` 放在 `~/.web-agent/workspaces/<目录名-8位哈希>/`（`workspaceStateDir()`，测试可用 `WEB_AGENT_STATE_DIR` 改根目录）。工程里只有模型自己写的文件；`<工作区>/.web-agent/instructions.md` 仍是可选的用户输入，程序不创建。
14. 侧栏能把 Edge 换成 Chrome：`/api/browser` 返回新 profile，`/api/health` 的 `browser.name` 跟着变；换回 Edge 后连接仍是 `ready`（登录态在各自 profile 里）。
15. 换浏览器全程有界面：切换开始约 1 秒内旧窗口仍显示、下拉置灰；新窗口出现时同样置灰；约 2 秒后下拉解锁、值变成新浏览器；切换完成后旧浏览器进程数为 0。
16. 单实例：已有进程在跑时再启动，会打印「Web Agent 已经在跑」并把原界面调到前面，然后退出，不产生第二个进程。

## 已知问题 / 坑

- Chrome 的隔离 profile 第一次是空的：用户说“Chrome 已经登录了”指的是日常 profile，
  浏览器安全策略不允许日常 profile 开调试端口，所以切换后仍要登录一次。

- **选择器是唯一脆弱点。** 真实站点的 class 是哈希（如 `_27c9245`），我们只用稳定的语义 class
  （`ds-message`、`ds-markdown`、`ds-button--primary`）。改版后先看 `src/site.mjs` 的 `pageProbe`。
- **等待判定是启发式。** “没有生成中信号 + 文字 3 秒没变”；极慢的流式输出可能被提前判定结束，
  真出问题调 `src/site.mjs` 里的 3000ms 稳定窗口。
- **审批条是浮层**，会遮住日志底部。功能没问题，视觉上可以再收进侧栏。
- **一次只跑一个任务**（`agent.busy` 直接 409）。多任务是刻意不做的。
- **关闭界面窗口不会结束进程**，目前靠 Ctrl+C。要改就得监听 `--app` 窗口关闭，跨平台不统一。
  反过来，关掉 DeepSeek 那个窗口会触发自愈：`web-agent.mjs` 里 `proc.once('exit')` → `recover()` 重开浏览器。
- **程序自己退出过一次（用户反馈）**：已确认一个真实成因——机器上残留了第二个 `web-agent.mjs`，和当前实例共用同一个浏览器 profile，一方切换/退出会把共享浏览器连带关掉。现在有单实例锁（见决策 18）。另一种可能是控制台被关 / Ctrl+C，日志里能看到信号。
  现在有 `~/.web-agent/app.log`，退出原因（SIGINT / SIGHUP / code）都会写进去；下次发生先看日志最后几行。
  另外 `unhandledRejection` / `uncaughtException` 不再直接带走进程，只记日志 + 界面 notice。
- **文件夹选择框只有 Windows 有实现**（PowerShell + WinForms）；其它平台 `pickFolder` 返回 null，
  界面里选目录会失败，只能靠 `-w` 指定。这是目前最明确的跨平台缺口。
- **界面右侧的留白**是工作台刻意的呼吸区（时间线列宽 760px，保证可读行长），
  `inspect.mjs` 会记一条 `hero-void` WARN，不算回归。
- **DeepSeek 网页端可能限流。** 没有频率控制；连续长任务如果被要求验证码，就是这里的问题。
- 真实模型的写法不完全受控：它可能把工具名写在围栏上、可能一轮多个块、可能先解释再给块。
  解析器已经兼容这三种，但**不要**再加“宽松到能执行普通代码块”的规则。
