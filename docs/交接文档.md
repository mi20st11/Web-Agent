# 交接文档

写给下一个接手的人（或下一个会话里的自己）。先读 README，这里只记“为什么这样做”和“哪里还脆”。

## 现状

v0.3，功能闭环，**已经在真实的 chat.deepseek.com 和 gemini.google.com 上跑通**（Windows 11 + Edge 156 / Chrome）。这一版把站点层拆成“公共流程 + 每站适配”，新增 Gemini；另把“启动前弹目录框”改成“先进界面、再选目录”，界面按 framed-sheet 重做。侧栏加了「网页端」下拉（DeepSeek / Gemini），选中后同一个窗口直接导航过去。

- 测试 20 个全绿，约 28 秒：协议 13、路径策略 5、真实 CDP 端到端 2（用 `test/mock-deepseek.html`）。
- 真实站点验证过两条链路：
  1. 「看目录 → 写 hello.txt → 读回来」：一轮解析出 `list` + `write` + `read` 三个工具，全部执行成功，中文内容读回一致。
  2. 「echo 你好 + node -v」：一轮解析出两个 `shell`，中文输出和 `v24.19.0` 都正确回传，模型据此给了结论。
- 危险命令审批链路在 mock 上验证：弹审批 → 拒绝 → 模型收到“用户拒绝” → 换方案。
- 工作区切换验证过：`POST /api/workspace` 切到空目录后，同一轮 `list`+`write`+`read` 写进了新目录（`ok.txt` = `done`）。
  默认提示词也因此改回直给式（见决策 10）。
- v0.2 冒烟：真实站点上一轮 `list` + 目录 `shell` + `write` + `read` 四个工具全部跑通（`smoke.txt` = `ok`），
  证明“没有启动目录、事后再选”不影响工具链。
- 界面回归：`design-taste-frontend` 的 `inspect.mjs --app` 在引导态和开始态都是 **0 FAIL**，
  只剩 1 条 WARN（工作台右侧留白 / 小字号占比），属于这类 devtools 界面的刻意选择。
- **未做**：macOS/Linux 实测、打包成单文件。

## 怎么跑

```bash
node web-agent.mjs                              # 起服务 + 界面，进去再选工程目录
node web-agent.mjs -w "D:\code\my-project"      # 直接指定工程目录
node web-agent.mjs --no-pick                    # 兼容旧参数，现在启动本来不弹框
node web-agent.mjs --no-window                  # 只起服务，打印界面地址
node web-agent.mjs --browser chrome             # 用 Chrome（独立 profile）
node web-agent.mjs --site gemini                # 用 gemini.google.com（会记住，下次不带也行）
node web-agent.mjs --site deepseek --browser edge
npm test                                        # 全部测试（会开无头浏览器）
npm run test:unit                               # 只跑协议和路径策略
```

首次启动会建独立 profile 并打开 DeepSeek，**登录一次**即可，之后复用。
Edge 用 `~/.web-agent/browser-profile`，Chrome 用 `~/.web-agent/chrome-profile`。

调试：`WEB_AGENT_DEBUG=1` 打印完整错误栈；`WEB_AGENT_BROWSER` 指定浏览器可执行文件。

## 关键决策

1. **不要扩展。** 旧版靠内容脚本 + MutationObserver，要处理 MV3 回收、消息广播、侧边栏生命周期，
   一半代码在跟浏览器打架。现在用 CDP 直接控制页面，问题只剩“页面长什么样”。
2. **独立 profile，不复用日常浏览器。** Chrome 136+ 会忽略默认 profile 上的
   `--remote-debugging-port`；独立 profile 同时也隔离了登录态。
3. **端口用 0，从 `DevToolsActivePort` 读。** 固定 9222 会跟别的工具打架，`/json/*` 在新版上也未必可靠。
4. **零依赖。** Node 22+ 自带 `WebSocket` 和 `fetch`，CDP 客户端只有 100 多行。没有 npm 安装步骤，
   clone 下来就能跑。
5. **工具协议用代码块。** 成对的中文标记又长又容易被模型改写；
   ```` ```tool ```` + 首行工具名更短，也允许一轮多个工具。同时兼容两种偷懒写法：
   围栏直接写工具名（` ```shell ` + 命令正文）、或 DeepSeek 丢掉块标签但首行正好是工具名。
6. **回传结果而不是让模型读文件。** 输出超过 8000 字符才落盘给路径，避免上下文爆炸。
7. **安全放在执行层，不放在提示词里。** `resolveInside`、`isDangerous`、Git 快照、日志是硬约束。
   模型被网页内容带偏时，最多多一次工具调用。
8. **界面是单文件 HTML。** 无构建、无框架、SSE 推状态。
9. **发送要像人，不要像脚本。** 用 `Input.insertText` + 可信 Enter（`Input.dispatchKeyEvent`），
   失败才用真实鼠标点按钮；不要用 JS 直接改 value + `click()`。发送成功靠消息数/URL/生成中状态确认，
   因为 DeepSeek 要等服务端响应后才清空输入框，按“输入框变空”判定会误报。
10. **提示词直给，不绕弯。** 结构就是：工程目录 + 环境 + 工具块写法 + 工具清单 + 几条纪律，
    不用“结对口吻/去身份化”的包装（早期试过，已放弃）。仍然不提 agent、爬取、反代这些词，
    因为 DeepSeek 有风控；但也不伪装成人类闲聊。想换措辞不用改代码：写 `<工作区>/.web-agent/instructions.md` 整段覆盖。
11. **工程目录是运行时状态，不是启动常量。** 启动不再弹框：先起服务、开界面，浏览器在后台连；
    工作区优先级是 `-w` > `~/.web-agent/config.json` 的 `lastWorkspace` > 空。
    `Agent.setWorkspace()` 会重建 policy、tools 和提示词，界面通过 `POST /api/workspace` 触发；
    不带 body 就弹 Windows 原生文件夹选择框（`src/pick.mjs`）。切换后不自动清空对话，只提示“建议先开新对话”。
    这样将来包成 exe 时，双击就是主界面，不会先卡在一个系统对话框上。
12. **界面是 framed-sheet 工作台，不是营销页。** 侧栏 228px + 48px 顶栏共用一层 tinted ground，
    右侧一张白色 sheet（1px 边、16px 圆角、无阴影）；时间线是“动作账本”，工具调用一行一个、1px 规则分隔，
    不做卡片堆叠。空状态在纸面里垂直居中，避免下半屏一整块死白。字体 IBM Plex Sans/Mono，主色 `#1b6c80`，
    正文 14px、元信息 11–12px。改样式前先跑 `inspect.mjs --app`，保持 0 FAIL。
13. **浏览器死了要自己爬起来。** 用户关掉 DeepSeek 窗口、浏览器崩溃、或启动时进程交接，都会让 CDP 断掉。
    `web-agent.mjs` 监听自己启动的浏览器进程，退出 1.2 秒后先确认“端口还在不在、页面还在不在”：
    只是进程交接就不动；真没了就重开浏览器并重新 attach（最多 3 次，任务进行中先等它跑完）。
    所有控制台输出同时写 `~/.web-agent/app.log`，退出原因（信号 / code）也写进去，用于排查“自己退出”。

14. **等回答用自适应采样。** 开头 300ms 一次抓首段，之后 550ms；见过流式输出后，静止 900ms 即提取（原来固定 3s）。真机单轮约 4 秒，mock 端到端从 22s 降到 13s。界面字体改成异步加载（`media="print"` + `onload`），国内网络不挡首屏；生成期间状态 pill 显示“正在生成…”。
15. **空状态只留一句话，但每次换一句。** 不再摆示例任务；有工作区、没有对话时，从 8 条 DeepSeek 风格问候里随机取一条
    （`sessionStorage['wa-greeting']` 排除上一条），发送后自动隐藏。侧栏底部是 `dsh-pet` 的鲸鱼娘（精致版）idle 序列帧，
    6 帧、按上游 `pet.json` 的 500/500/600/500/500/600 ms 播放，`prefers-reduced-motion` 下停在第一帧。
    它可以拖到窗口任意位置（`position:fixed`，指针事件 + `setPointerCapture`，四周留 8px 边界，
    位置存 `localStorage['wa-mascot-pos']`，刷新后原地出现），除此之外不响应点击。素材按 Apache-2.0 署名，来源、commit 和修改说明写在
    `ui/index.html` 的注释与 `THIRD_PARTY_NOTICES.md` 里。引导态仍保留三步说明和最近目录。

16. **运行时可以换浏览器。** `POST /api/browser {"name":"edge|chrome"}` 会接上另一个浏览器的独立 profile 重连；
   选择写进 `~/.web-agent/config.json` 的 `browser` 字段。`--profile` / `--cdp` 启动时不能换（界面里置灰）。
   Chrome 首次使用需要在它自己的 profile 里登录一次；未登录时顶部连接状态显示「未登录」，控制台也有一行提示。

17. **换浏览器＝替换：新浏览器接上、界面窗口搬过去、旧浏览器关掉。**
    `switchBrowser()` 把旧的 launch 交给 `connect({ closeOld: old })`：先在新浏览器里
    `ensureAppWindow(port, wsPath, {create: true})` 开界面窗口、轮询等界面页真的出现，出现了才
    `closeBrowser(old, {timeoutMs: 800})` 并把它从 `runtime.opened` 里摘掉；新窗口没出来就保留旧的
    （宁可暂时两个，也不能把界面关没）。这样任何时刻只剩一个浏览器，任务栏里不会留下点不开的图标。
    中途试过“界面窗口留在旧浏览器”的无缝版：视觉上确实不跳，但两个浏览器并存，旧浏览器里的隐藏页
    在任务栏点了没反应，用户明确要求换完只剩一个，于是改回替换。
    窗口位置要归一化：浏览器会记住上次窗口位置，以前挪到屏幕外的坐标会被恢复成“半个窗在屏幕外”。
    所以 `connect()` 末尾对对话页跑一次 `revealWindow()`（在屏上的不动），`ensureAppWindow()` 对新开的
    界面窗口 `force: true` 摆到 `{left:10, top:10}`，对话窗口留在 `{left:90, top:80}`，两个窗口不重叠。

18. **单实例用 `~/.web-agent/instance.json` 锁。** 两个进程共用同一个浏览器 profile 时，任何一方切换或退出都会把共享浏览器关掉，另一边看起来就是“程序自己没了”。启动时如果记录的 pid 还活着、版本一致、`/api/health` 能通，就直接把已有界面叫到前面并退出；`--force` 绕过。这同时解释了之前“执行完自动退出”的一个真实成因：不是任务，是另一个实例在抢。
    光能打开界面不算健康：旧实例的浏览器断开后（用户关了对话窗口），界面还在、模型列表却是空的，再启动只会把那个空界面调到前面，看起来就是“打开没反应”。现在会读 `/api/health` 的 `connection`，等 1.5 秒再确认一次，仍不是 `ready` 就 `taskkill /T /F` 接管并重新连浏览器。

19. **换网页端是在同一个标签页里导航。** `GET /api/state` 带 `site:{key,label,canSwitch}`，`POST /api/site {"key":"gemini"}` 切换。
    实现是 `Page.navigate` 到新站点、按新 match 重新 attach、新建站点对象、`waitReady`，再 `saveConfig({site})`；失败回滚 `siteKey/siteDef/siteUrl/match` 并导航回旧地址。
    用 `--url` / `--match` / `--cdp` 启动时 `canSwitch:false`，下拉置灰（这些参数指定了固定页面）。
    没用 iframe 或第二个窗口：同一标签页切换最省，浏览器 profile、登录态、界面窗口都复用；代价是切站会离开当前对话页面。
    模型下拉已按用户要求去掉：不写死模型列表，也不再读页面模式菜单。

20. **切换反馈只走顶部胶囊，不写进对话时间线。** 换浏览器/换网页端原来会 `agent.push({type:'notice'})`，
    对话里就多出「正在切到 X…」「已切到 X」两条，和正文混在一起很吵。现在服务端不再推这两类 notice（失败也只回 400，
    由界面自己 toast），界面统一用 `#toast`：固定在顶部正中、`border-radius:999px` 的深色胶囊，
    `backdrop-filter: blur(12px)`，进场 `translateY(-16px) scale(.94)` → 0 配 `cubic-bezier(.22,1.28,.36,1)`（轻微回弹），
    2.4 秒后淡出。`toast()` 是唯一入口，所以所有提示（复制、切目录、清空…）都是同一个胶囊。

21. **换浏览器要“无缝”：启动时把另一个浏览器预热到屏幕外，切过去只是把窗口搬回来。**
    冷启动另一个浏览器要 3.2 秒（开进程 + 开窗口 + 加载页面），而切到已开着的浏览器只要 0.1 秒。
    所以 `connect()` 结束、`if (!info.switching)` 时跑一次 `warmOther()`：用对方 profile 起一个浏览器，
    `extraArgs: ['--window-position=-32000,-32000','--window-size=1280,860']` 把窗口摆到屏幕外，页面照常加载、登录态照常在。
    切过去时 `revealWindow({port, wsPath, urlIncludes: runtime.match})` 用 `Browser.getWindowForTarget` + `getWindowBounds`
    判断窗口是不是在屏幕外（`left/top <= -1000` 或最小化），只有是才 `setWindowBounds({left:90, top:80})`，
    已经在屏幕上的窗口不动。实测切换 0.09–0.18 秒。
    代价：启动时会多一个浏览器进程（内存多一份），`--no-window` / `--headless` / `--cdp` 时不预热。

22. **exe 用 `winexe` 子系统，双击不弹 CMD；界面窗口关掉就是退出。**
    没有控制台后 `console.log` 写不出去，`src/log.mjs` 的 `teeConsole` 包了 try/catch，`web-agent.mjs` 给
    `process.stdout/stderr` 挂了空的 `error` 监听。`build/launcher.cs` 里 `CreateNoWindow = true`，
    出错从「按任意键继续」改成 `MessageBox`。
    退出不用按钮：`watchUiWindow()` 每 2 秒在 `uiWindowPort` 上找 `server.url` 那个界面页，连续两次找不到就
    `shutdown(0, '界面关闭')`。原来是界面右上角的「退出」按钮 + `/api/quit`，用户要求去掉——关窗口就是退出。
    根目录的 `启动.cmd` 已删（双击它必然带一个 CMD 窗口），启动一律双击 `build\Web Agent.exe`。

23. **不在启动时预热第二个浏览器，改成“碰下拉才热”。**
    启动就开第二个浏览器，用户会看到多一个浏览器进程/按钮，反馈“打开 Web Agent 自动打开两个浏览器”。
    改成界面在 `browser-select` 的 `pointerdown`/`focus` 时打一次 `POST /api/warm`（整个会话只打一次），
    主进程再 `warmOther()`：用对方 profile 起浏览器、`--window-position=-32000,-32000` 把窗口摆到屏幕外，
    起来后立刻 `hideWindow()` 最小化——屏幕外的窗口在任务栏点了不出现，最小化的点了能回来。
    启动时不热，只有真要换浏览器时才有第二个进程。

24. **Gemini 的文字不走 CDP insertText，直接按行拼 DOM。**
    Quill 每插入一个换行都要重新排一次版：50 行、1.2KB 的正文用 `Input.insertText` 要 2.5–3 秒
    （1600 字不含换行只要 0.15 秒），用户看到的就是「文字在输入框里停五六秒才发出去」。
    `ChatSite` 现在把写入抽成可覆盖的 `async typeInto(text)`；`GeminiSite` 覆盖它，调 `pageInsertText`：
    `document.createElement('p')` 逐行建节点（空行 `<p><br></p>`）、`replaceChildren`、派发一次 `input` 事件。
    实测 50 行 236 毫秒，回车后 250 毫秒消息就出现在页面上。
    正文保真：Gemini 的 `user-query` 里读回的是单换行 + 空行原样（write 工具落盘 `alpha\n\nbeta\n` 验证过），
    比 innerText 可靠——innerText 会把每个 `<p>` 渲染成两个换行，别拿它判断内容。

25. **页面打不开 ≠ Cookie 被禁。** 断网/代理没开时 Chrome 会显示自己的错误页：目标的 URL 是
    `chrome-error://chromewebdata/`，但页面文档可能已经是 `about:blank`，`localStorage` 一读就抛错，
    于是被误判成「浏览器禁用了网站数据」。现在两个站点的 `pageProbe` 都返回 `loadError`
    （取 `.error-code` 文案，空白文档则记“页面没加载出来”），`check()` 原样透传：
    `refreshPage()` 把它映射成 `connection: 'error'` + 文案「页面没打开：ERR_…」，界面上直接看得到；
    `waitReady()` 遇到 `loadError` 每 3 秒 `Page.reload` 一次，`watchPage()` 之后每 15 秒再重载，
    代理晚开、网络抖一下都能自己恢复，不用用户重开窗口。
26. **本地接口的失败必须带 `error` 字段。** 界面 `api()` 的兜底文案是 `HTTP ${res.status}`，
    而 `/api/focus` 曾经返回 `200 {ok:false}` 没有 error，用户看到的就是一条「HTTP 200」的提示。
    现在 `/api/focus` 失败时给「没找到对话窗口，在浏览器标签页里点一下」，`/api/stop` 空转给
    「没有正在生成的回答」，`api()` 在 200 但 `ok:false` 时也回「操作没成功」，不再出现裸状态码。
27. **界面窗口就是主窗口，看门狗宁可晚退也不能误杀。** 用户反馈「切换浏览器后任务栏点不开」，
    日志是「旧窗口已关闭」紧接「退出 code=0 界面关闭」——`watchUiWindow()` 每 2 秒查 `uiWindowPort`
    上有没有界面页，切换时新窗口还没开出来，两次没查到就把整个程序退了，任务栏图标成了死进程。
    现在：`runtime.switching` 期间不计数；`listPages` 返回 null（浏览器没了）交给 `recover`，不算一次；
    连续 3 次才判定「用户关了窗口」。`ensureAppWindow()` 开完窗口后轮询最多 6 秒等界面页真的出现，
    确认了才把 `uiWindowPort` 指过去（换浏览器时不建新窗口，见决策 17）。
    另一个坑：预热把对方窗口放在 `-32000,-32000`，界面窗口会继承这个位置——`ensureAppWindow()`
    找到界面页后也调 `revealWindow()`，屏幕外的窗口搬回 `{left:90, top:80}`。

28. **页面连接断了要自己接回来；切网页端不能把整个程序卡住。** 对话窗口被关掉（或标签页崩了）时，
    `CDP` 把 pending 全部 reject 成「CDP 连接已关闭」，页面探测一路失败，界面就永远停在
    「未就绪 / CDP 连接已关闭」，连「网页端」下拉都切不动——用户看到的就是「切到 DeepSeek 还显示
    Gemini 未就绪」。现在 `connect()` 给每条页面连接挂 `cdp.on('__close')`，确认还是当前连接就置
    `connecting` 并在 300 毫秒后 `recover(..., { quick: true })`；`recover()` 先看浏览器还在不在
    （`listPages` 里还有任意 page 就算活着），活着就 `connect()` 重新接上（`connect()` 只认站点页在不在，
    缺了直接 `createTarget`，不再干等 8 秒），实测关掉对话窗口约 1.4 秒回到 `ready`。
    切网页端也不再 `await` 导航完成：`Page.navigate` 给 2 秒上限，然后用 `tab.evaluate('location.href')`
    确认文档真的换成新站点（`/json/list` 的 url 不可信，导航失败时它也显示目标地址），6 轮确认不到就回滚到
    原站点并报「打不开 X：页面没加载出来（网络断了？）」；`refreshPage()` 丢到后台跑，下拉 0.1–4 秒就有回应。
    协议层的「CDP 调用超时：Runtime.evaluate」也翻译成「页面没响应（网络断了？）」，不直接甩给用户。

## 真实站点适配实况（改版时对照）

页面（Edge 156 / 2026-11）关键事实：

- 输入框是 `<textarea>`，**没有** `id="chat-input"`，placeholder「给 DeepSeek 发送消息 」；
  页面上还有一个不可见的 `<input>`，选择器必须按“可见”过滤。
- 发送按钮是 `div[role="button"]`，class 含 `ds-button--primary`、`ds-button--circle`；
  **没有 aria-label**；输入框为空时多一个 `ds-button--disabled`。
- 生成中没有任何 `stop` 元素，唯一可靠信号是“发送圆圈按钮去掉 disabled + 输入框为空”。
- 用户消息也是 `.ds-message`；助手正文是 `.ds-markdown.ds-assistant-message-main-content`。
- 代码块：`.md-code-block` > `.md-code-block-banner-wrap` > `.d2a24f03 span`（语言文字，如 `tool`），
  代码在紧随的 `<pre>` 里，每行一个 `<span>`，`textContent` 能还原换行。
- 提取时**必须保留换行**：把代码块换成文本节点后，普通 `white-space` 会让 `innerText` 把 `\n` 折成空格，
  导致工具块解析失败。现在替换节点带 `white-space: pre-wrap`。

已知的联动坑：

- Edge 登录微软账号后，同步会把账号里的“阻止所有 Cookie”同步到专用 profile，
  表现为 `<html>` 只有几 KB、`#root` 空、`SecurityError: sessionStorage Access is denied`。
  启动参数已加 `--disable-sync`；改本地 `Preferences` 前必须先让所有 msedge 进程退出，否则退出时会写回。
- 关闭浏览器用 `closeBrowser()`：先 CDP `Browser.close`，等 6 秒，再 `taskkill /T /F`。直接 taskkill 会留下锁文件。

## Gemini 适配实况（2026-11，Chrome）

选站点：`--site gemini`（或 `--url https://gemini.google.com/app`），选择写进 `~/.web-agent/config.json` 的 `site`。
`web-agent.mjs` 里的 `SITES` 表负责 label / 默认 URL / 页面匹配串 / 站点类，界面上的名字来自 `agent.snapshot().siteName`。

- 登录是个坎：Google 拒绝在带 `--remote-debugging-port` 的 Chrome 里登录（提示“该浏览器不安全”）。
  绕法：先用同一个 `--user-data-dir` 起一次**不带调试端口**的普通 Chrome，登录 Gemini，关掉，
  再由 Web Agent 带调试端口重开——登录态已落盘，不会再触发检查。
- 编辑器是 Quill：`rich-textarea div.ql-editor[contenteditable=true]`；旁边还有一个不可见的 `.ql-clipboard`，
  必须按可见过滤。发送按钮 `button[aria-label="发送"]`（英文界面可能是 Send），输入为空时不出现。
- **页面强制 Trusted Types**：`innerHTML = ''` 会抛 `TypeError: ... requires 'TrustedHTML' assignment`。
  清空只能 `execCommand('selectAll') + delete`，兜底 `replaceChildren`；写入兜底 `execCommand('insertText')`。
- 回答：`<model-response>` → `model-response-content` → `.model-response-text` / `.markdown`。
  追问建议条 `<follow-up>` 在 `.markdown` 内部（innerText 会混进“Want me to …?”），提取时要删。
- 代码块是自定义元素 `<code-block>`，语言在 `.code-block-decoration` 头部，代码在 `<pre>`。
- 生成中：`button[aria-label="Stop response"]`（英文界面）/“停止回答”。`newChat` 页面上找不到按钮，
  靠公共兜底 `Page.navigate(this.url)` 回 /app。
- 用户点“停止”后回答区只有一句 “You stopped this response”，正文为空。`ask()` 现在用
  `emptyGraceMs`（DeepSeek 0，Gemini 25000）判断“新消息已出现但一直没正文”，直接报 `EXTRACT_EMPTY`，
  不再干等到 60 秒超时。

## 已知问题 / 坑

- **Chrome 的隔离 profile 第一次是空的**：用户说“Chrome 已经登录了”指的是日常 profile，
  浏览器安全策略不允许日常 profile 开调试端口，所以切换后仍要登录一次。Gemini 还要多一步：
  先不带调试端口登录一次，见上面 Gemini 一节。
- **Gemini 的 `emptyGraceMs` 是 25 秒**：占位气泡出来后 25 秒还没正文才报“回答是空的”；第一版设 8 秒，实测有时正文十几秒才渲染出来，会误报。
  真遇到就调 `src/gemini.mjs` 构造里的这个值。
- **切站会离开当前对话页面**：实现是同一标签页直接导航，切到另一个站点再切回来时，原来的对话页不在了（Gemini 的历史对话还在侧栏里）。**

- **选择器是唯一脆弱点。** 真实站点的 class 是哈希（如 `_27c9245`），我们只用稳定的语义 class
  （`ds-message`、`ds-markdown`、`ds-button--primary`）。改版后先看 `src/site.mjs` 的 `pageProbe`。
- **等待判定是启发式。** “没有生成中信号 + 文字 3 秒没变”；极慢的流式输出可能被提前判定结束，
  真出问题调 `src/site.mjs` 里的 3000ms 稳定窗口。
- **审批条是浮层**，会遮住日志底部。功能没问题，视觉上可以再收进侧栏。
- **一次只跑一个任务**（`agent.busy` 直接 409）。多任务是刻意不做的。
- **关闭界面窗口不会结束进程**，目前靠 Ctrl+C。要改就得监听 `--app` 窗口关闭，跨平台不统一。
  反过来，关掉 DeepSeek 那个窗口会触发自愈：`web-agent.mjs` 里 `proc.once('exit')` → `recover()` 重开浏览器。
- **程序自己退出过一次（用户反馈）**：已确认一个真实成因——机器上残留了第二个 `web-agent.mjs`，和当前实例共用同一个浏览器 profile，一方切换/退出会把共享浏览器连带关掉。现在有单实例锁（见决策 18）。另一种可能是控制台被关 / Ctrl+C，日志里能看到信号。
  现在有 `~/.web-agent/app.log`，退出原因（SIGINT / SIGHUP / code）都会写进去；下次发生先看日志最后几行。
  另外 `unhandledRejection` / `uncaughtException` 不再直接带走进程，只记日志 + 界面 notice。
- **文件夹选择框只有 Windows 有实现**（PowerShell + WinForms）；其它平台 `pickFolder` 返回 null，
  界面里选目录会失败，只能靠 `-w` 指定。这是目前最明确的跨平台缺口。
- **界面右侧的留白**是工作台刻意的呼吸区（时间线列宽 760px，保证可读行长），
  `inspect.mjs` 会记一条 `hero-void` WARN，不算回归。
- **DeepSeek 网页端可能限流。** 没有频率控制；连续长任务如果被要求验证码，就是这里的问题。
- 真实模型的写法不完全受控：它可能把工具名写在围栏上、可能一轮多个块、可能先解释再给块。
  解析器已经兼容这三种，但**不要**再加“宽松到能执行普通代码块”的规则。
